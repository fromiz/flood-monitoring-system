# V8.5.26 CCTV GPU/CPU 안정화

이번 버전은 사용자가 다시 첨부한 `pohang_cctv.py`를 기준 파일로 사용하고 V8.5.24 WebSocket 호환 코드만 다시 결합했습니다.

## 핵심 수정

- `best.pt`는 차량 위치(box)만 담당합니다.
- 검출된 차량 bbox를 crop한 뒤 `tire_level.pt`를 먼저 실행합니다.
- 해당 차량 crop에서 타이어가 검출되지 않은 경우에만 `car_flood_cls.pt`를 fallback으로 실행합니다.
- 업로드된 `tire_level.pt`를 `weights/tire_level.pt`에 그대로 포함했습니다.
- 약한 차량 박스가 2회 확인된 다음 confirmation 상태에서 제거되어 다음 프레임에 다시 사라지던 버그를 수정했습니다. 이제 확인된 약한 차량은 계속 재확인되므로 박스가 번갈아 깜빡이지 않습니다.
- GPU에서는 best.pt 검출 주기를 빠르게 하고, Optical Flow로 박스를 억지 이동시키지 않습니다. 오래된/틀어진 LK 박스 대신 새 best.pt bbox를 우선합니다.
- GPU에서 너무 늦게 끝난 차량 검출은 현재 프레임에 적용하지 않고 폐기합니다.
- `tire_level`과 `car_flood_cls`는 하나의 stage lock을 공유하지만 `best.pt` 차량 검출 lock과는 분리했습니다. 침수 단계 분류가 차량 박스 갱신을 막지 않습니다.
- Ultralytics에서 반복 출력되던 deprecated `half=` predict 인자를 제거했습니다. CUDA 장치 사용 자체는 유지합니다.
- GPU판은 최대 6개의 열려 있는 CCTV까지 불필요하게 AI 주기를 늘리지 않습니다.

## GPU 기본값

- `AI_DEVICE=cuda`
- 차량 bbox: 약 0.22초 간격
- 침수 단계: 약 0.85초 간격
- 원거리 rescue: 약 1초 간격
- GPU에서는 LK Optical Flow 장기 보간을 사용하지 않음

## CPU 기본값

CPU판은 같은 판정 순서를 유지하되 부하를 줄이기 위해 검출/분류 주기가 더 느립니다.

## 모델 순서

`best.pt -> vehicle crop -> tire_level.pt -> (no tire only) car_flood_cls.pt`
