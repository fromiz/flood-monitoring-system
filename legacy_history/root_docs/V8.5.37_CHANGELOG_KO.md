# V8.5.37 변경사항

## 1. 박스 미표시 원인 범위 수정
V8.5.36 실환경 로그에서 WebSocket은 `annotated=True`였지만 `detmeta=0`, `result_age=None`이 반복되었습니다. 즉 브라우저/렌더러가 아니라 `CameraWorker`의 AI producer가 첫 결과를 publish하지 못한 상태였습니다.

V8.5.37은 다음을 변경합니다.
- 짧은 annotated lease 자체를 AI 실행 게이트로 사용하지 않고, 한 번 구독되면 worker 수명 동안 유지되는 `ai_activation` 이벤트 사용
- `cctv-box-detector`를 critical thread로 취급해 죽은 AI thread가 붙은 worker를 재사용하지 않음
- dead worker 교체 전 `stop()` 호출
- AI thread 상태/heartbeat/attempt/success 진단 추가
- 첫 live inference는 full-frame best.pt 단일 pass를 우선해 즉시 publish하고, tiled rescue는 첫 성공 이후부터 필요할 때만 수행
- trusted test CCTV의 background recorder는 모델 추론 대신 신뢰된 baseline만 기록하여 브라우저가 열리기 전 best.pt/tire/body GPU 경합 제거
- public background scan 시작 지연을 20초로 늘려 대시보드 live AI 우선권 확보

PowerShell 진단 예:
- `CCTV AI37 thread-start [...]`
- `CCTV BOX37 raw=... visible=... stage=...`
- `CCTV WS37 annotated=... ai_alive=... ai_state=... detmeta=... result_age=...`

## 2. 하단 침수 알림은 단계 변경 때만 표시
DB/그래프용 주기 기록은 그대로 유지합니다. 다만 하단 침수 알림 목록은 `/api/events?...&changes_only=true`를 사용해 카메라별 단계가 실제로 변한 기록만 표시합니다.

예:
- Lev1 -> Lev1 -> Lev1: 첫 Lev1 카드만 표시
- Lev1 -> Lev2: Lev2 카드 새로 표시
- Lev2 -> Lev0 -> Lev1: 다시 Lev1이 되면 새 카드 표시

따라서 이 변경은 역사/그래프/지도 consensus 저장 주기를 훼손하지 않습니다.

## 3. FULL 파이프라인 유지
`best.pt -> vehicle crop -> tire_level.pt -> (타이어 미검출 시) car_flood_cls.pt` 순서를 유지합니다.
