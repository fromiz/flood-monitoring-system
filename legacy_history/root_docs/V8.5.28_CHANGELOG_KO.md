# V8.5.28 - CCTV 실시간성 + 차량/침수 박스 복구

이번 버전은 화면 버퍼링과 `vehicles 0`/박스 미표시 문제를 분리해서 수정했습니다.

## 1. CCTV 영상 버퍼링

- 현재 코드는 이미 `grab / vehicle AI / stage AI / privacy / render`를 별도 스레드로 실행합니다. 따라서 영상과 AI가 같은 메인 스레드에 있다는 가정 대신 실제 병목을 수정했습니다.
- GPU 화면 렌더 제한을 9fps -> 15fps로 올렸습니다.
- WebSocket 전송 제한을 선택 화면 약 10fps, 다른 화면 약 5fps에서 선택 화면 약 15fps, 다른 화면 약 12fps로 올렸습니다.
- 브라우저가 JPEG를 디코딩하는 동안 새 프레임이 들어오면 방금 디코딩한 프레임을 버리던 로직을 제거했습니다. 이 로직은 부하가 높을 때 `decode -> 새 패킷 -> 폐기`가 계속 반복되어 화면이 멎은 것처럼 보일 수 있었습니다.
- HLS는 첫 접속부터 최신 세그먼트를 우선 사용하고, prefetch 큐를 1개짜리 최신 프레임 방식으로 바꿨습니다. 오래된 세그먼트를 순서대로 뒤쫓지 않습니다.

## 2. 차량/침수 단계 박스

- V8.5.27은 여러 카메라에서 `best.pt`가 정상 검출해도 추론 도중 capture frame이 앞서가면 결과를 stale로 보고 버릴 수 있었습니다. 성공한 차량 검출 결과를 버리지 않고 최신 프레임까지 제한적으로 좌표를 전달한 뒤 즉시 게시하도록 바꿨습니다.
- `best.pt` 검출 confidence 기본값을 0.12, 원거리 rescue를 0.08로 조정했습니다. 약한 박스는 바로 표시하지 않고 시간축 confirmation(2~3회)을 통과해야 표시됩니다.
- 한 번 확인된 약한 차량은 다음 검출에서 confidence가 약간 흔들려도 confirmation 상태를 유지합니다.
- 놓친 AI 주기를 최대 2회까지 유지해서 박스가 한 프레임씩 사라졌다 나타나는 현상을 줄였습니다.
- stage 결과는 best.pt에서 부여한 `track_id`를 그대로 유지합니다. 늦은 `tire_level/car_flood_cls` 결과를 이웃 차량에 다시 association하지 않습니다.

## 3. 요청한 침수 모델 순서 유지

1. `best.pt`로 차량 검출
2. 각 차량 bbox crop
3. `tire_level.pt`로 타이어 침수 단계 판정
4. 해당 차량 crop에서 타이어 결과가 없을 때만 `car_flood_cls.pt` 차체 분류 fallback
5. 결과는 원래 `best.pt` 차량 bbox/track_id에 합성

`tire_level.pt`를 삭제하거나 우회하지 않습니다.

## 4. RTX GPU 스케줄링

- `best.pt` 차량 geometry는 전용 lock/우선순위를 사용합니다.
- `tire_level -> car_flood_cls`는 하나의 stage lock을 공유해 같은 GPU에서 stage CUDA 작업끼리 난립하지 않게 했습니다.
- stage 작업이 대기 중일 때 새 차량 geometry 요청이 들어오면 geometry가 먼저 GPU를 사용할 수 있게 했습니다.
- stage 분류는 가장 강한 차량 crop으로 제한해 한 카메라가 GPU를 오래 독점하지 않게 했습니다.

## 5. 오류 확인

차량 detector 또는 tire/body pipeline에서 예외가 나면 5초 간격으로 콘솔에 원인을 출력합니다. 영상 렌더는 계속 유지합니다.
