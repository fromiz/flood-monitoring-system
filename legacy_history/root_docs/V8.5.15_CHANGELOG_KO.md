# V8.5.15 변경 사항

기준 소스: 사용자가 다시 첨부한 `flood-monitor-v8.5.14(1).zip`

## 확인된 원인

1. 빠른 차량 박스 검출과 느린 타이어/차체 침수 단계 분류가 같은 AI 루프에서 순차 실행되어, 단계 분류 중에는 새 박스 검출이 멈췄습니다.
2. 박스 결과와 단계 결과가 하나의 최신 패킷을 공유해, 늦게 도착한 단계 패킷이 더 최신 박스 패킷을 가릴 수 있었습니다.
3. 네트워크 CCTV 직접 연결이 실패하면 HLS 복구 함수가 같은 직접 연결을 한 번 더 시도하여, 첫 화면의 연결 제한 시간이 중복됐습니다.

## 수정 내용

- 차량 박스 검출 스레드와 침수 단계 분류 스레드를 실제로 분리했습니다.
- 단계 분류 작업은 대기열을 쌓지 않고 가장 최신 작업 하나만 유지합니다.
- 박스 패킷과 단계 패킷을 독립 저장하고, 현재 트랙 ID에 단계 라벨만 합칩니다.
- 단계 패킷은 과거 프레임의 좌표·속도·추적 정보를 덮어쓰지 않습니다.
- 직접 연결 실패 뒤 HLS 복구에서는 OpenCV 직접 연결을 재시도하지 않습니다.
- CCTV 창을 연 즉시 연결 상태 JPEG가 송출되는 기존 V8.5.14 동작은 유지했습니다.
