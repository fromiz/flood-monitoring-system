# V8.5.19 변경 사항

기준: V8.5.18 전체 코드, 사용자 제공 화면 녹화와 오류 화면

## 1. CCTV 창이 `CCTV 연결 중`에서 멈추는 문제 보강

- 포항 UTIS 요청에 브라우저형 `User-Agent`, `Referer`, `Origin` 헤더를 적용했습니다.
- `//주소` 형식의 프로토콜 상대 URL을 HTTPS 주소로 정규화합니다.
- HLS 세그먼트를 `.ts/.m4s` 확장자로만 판단하던 제한을 제거했습니다. 확장자가 없는 미디어 세그먼트 URL도 처리합니다.
- OpenCV가 공개 CCTV를 직접 열지 못하면 requests 기반 HLS 재생목록/세그먼트 방식으로 전환합니다.
- HLS 세그먼트를 임시 로컬 파일로 디코딩한 뒤 원본 FPS에 맞춰 재생하여 한 프레임만 보이고 멈추는 현상을 줄였습니다.
- 재생목록이 아직 다음 세그먼트로 넘어가지 않은 정상 대기 상태를 연결 실패로 처리하지 않습니다.
- 연결 실패 안내 JPEG를 분석 스트림뿐 아니라 비포커스 원본 스트림에도 전달합니다.

## 2. 상단 상태의 `Failed to fetch` 보강

- MJPEG generator가 새 프레임을 무한정 기다리면서 서버 worker thread를 계속 점유하던 구조를 수정했습니다.
- 1초 단위 keepalive JPEG를 반환하여 멈춘 CCTV 창이 많아져도 다른 상태 API가 굶지 않도록 했습니다.
- `/api/health`, 환경 DB 상태, CCTV 백그라운드 상태, CCTV worker 상태를 비동기 상태 조회로 변경했습니다.
- 프런트엔드 상태 조회에 timeout + 재시도를 추가했습니다.
- 일시적인 네트워크 실패는 즉시 고정 오류로 남기지 않고 `재연결 중` 경고로 표시합니다.

## 3. 통합 침수 GeoJSON 오류 복구

- 침수 GeoJSON 요청에 재시도 로직을 추가했습니다.
- 오류 시 오래된 침수 영역은 기존처럼 fail-closed로 제거합니다.
- 이후 정상 응답을 받으면 `통합 DEM 침수 GeoJSON 정상` 상태로 다시 복구되도록 수정했습니다.

## 4. 실시간 CCTV 우선 설정

- 포함된 `.env`의 `BACKGROUND_CCTV_WORKERS`를 `4`에서 `1`로 조정했습니다.
- 여러 백그라운드 AI 작업보다 사용자가 실제로 열어 본 CCTV 스트림의 연결/표시를 우선합니다.

## 5. 검증

- Python 전체 테스트: `38 passed`.
- 번들 테스트 CCTV `app/static/media/flood-test-01.mp4`를 실제 CameraWorker로 열어 서로 다른 연속 JPEG 프레임이 생성되는 것을 확인했습니다.
- Python 문법 검사와 프런트엔드 JavaScript `node --check`를 통과했습니다.

외부 포항 CCTV 원본 서버는 실행 환경의 네트워크 제한에 따라 여기서 실시간 끝단까지 직접 검증할 수 없으므로, 공개 CCTV 자체의 일시 중단까지 보장하는 변경은 아닙니다. 대신 직접 OpenCV 연결이 실패할 때 HLS 요청 방식으로 자동 전환하고, 화면과 상태 API가 함께 멈추지 않도록 복구 경로를 추가했습니다.
