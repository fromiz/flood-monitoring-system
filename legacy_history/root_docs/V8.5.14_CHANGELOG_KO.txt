포항 침수 통합관제 V8.5.14 변경 사항

중요한 버전 기준 정정
- V8.5.13은 V8.5.11 원본에 직접 패치한 버전이 아닙니다.
- 당시 작업 공간에 남아 있던 V8.5.7 전체 프로젝트를 기준으로 V8.5.13 기능을 다시 적용했습니다.
- 따라서 V8.5.11에서 정상적이었던 일부 동작이 회귀할 가능성이 있었고, 이번 V8.5.14에서 확인된 회귀 경로를 수정했습니다.
- V8.5.11과 파일 단위의 정확한 비교가 필요하면 원본 V8.5.11 ZIP이 필요합니다.

1. CCTV 버퍼링 감소
- 네트워크 프레임 읽기 자체가 이미 늦어진 경우 추가 프레임 대기를 하지 않습니다.
- 로컬 파일은 원본 FPS로 재생하고, 빠르게 풀리는 HLS 세그먼트만 남은 시간만큼 제한합니다.
- CCTV 창이 하나라도 열려 있으면 로컬 테스트 백그라운드 분석이 별도 모델 작업을 시작하지 않습니다.
- 열린 영상의 실시간 추론이 15초 주기의 백그라운드 분석과 경쟁하던 현상을 제거했습니다.

2. 차량 박스 추적
- 빠른 차량 탐지 결과만 현재 프레임의 박스 좌표를 갱신합니다.
- 늦게 도착한 타이어·차체 침수 단계 결과는 현재 추적 중인 박스의 단계·라벨만 변경합니다.
- 과거 프레임의 좌표가 다시 적용되어 박스가 뒤로 튀는 회귀를 제거했습니다.
- LK 특징점을 늘리고 차량 이동 속도를 짧게 유지해 특징점이 잠시 끊겨도 박스가 도로에 멈추지 않게 했습니다.

3. 침수심 그래프 즉시 표시
- CCTV 창을 만드는 순간 현재 단계로 조회 시작점과 현재 시점 두 점을 생성합니다.
- 서버 응답 전에 수평 단계선이 바로 표시됩니다.
- 첫 번째 요청은 저장된 침수 단계만 빠르게 조회합니다.
- 강수·하수·하천 이력은 두 번째 요청으로 채워지며 그래프 표시를 막지 않습니다.
- 저장된 값이 한 점뿐이어도 조회 구간 끝까지 이어서 선으로 표시합니다.

4. 클릭 전 침수 단계 저장
- 서버 시작 시 테스트 CCTV의 신뢰 기준 단계를 데이터베이스에 동기 방식으로 먼저 저장합니다.
- CCTV 창을 열지 않아도 로컬 테스트 기록기가 계속 저장합니다.
- CCTV가 열려 있을 때는 중복 모델 분석 없이 신뢰 기준 또는 열린 워커의 값을 저장합니다.
- 저장 이력은 이후 사용자 지정 기간 검색에서도 조회할 수 있습니다.

5. 테스트 CCTV 색상 유지
- 테스트 CCTV에 최소 단계와 신뢰 기준 정보를 목록 API가 함께 전달합니다.
- 브라우저는 첫 목록 표시, 60초 주기 갱신, 실시간 분석 갱신 모두 같은 단계 정책을 사용합니다.
- 서버 목록, 이벤트, 저장 행, 이력 그래프, 지도에서 테스트 최소 단계를 마지막 단계에 적용합니다.
- 지도에서 최소 단계를 적용한 뒤 열린 영상 Lev0으로 다시 덮어쓰던 순서를 수정했습니다.

6. 단계 동률 정책
- 차량 수가 많은 단계가 우선입니다.
- 차량 수가 같으면 단계별 평균 신뢰도가 높은 단계가 우선입니다.
- 평균 신뢰도까지 완전히 같으면 높은 단계가 선택됩니다.

검증
- Python 전체 구문 검사 통과
- JavaScript 구문 검사 통과
- 차량 수 우선·평균 신뢰도 동률·완전 동률 정책 3건 통과
- 테스트 CCTV 최소 단계 서버 정책 3건 통과
- 브라우저 테스트 CCTV 단계 및 주기 갱신 회귀 정책 3건 통과
- 현재 검사 환경에는 pytest 실행기가 없어 기존 pytest 모음 전체는 실행하지 못했습니다.

보안
- 배포 ZIP에는 .env, API 키, 데이터베이스와 실행 캐시를 포함하지 않습니다.
