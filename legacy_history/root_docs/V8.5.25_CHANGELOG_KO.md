# V8.5.25 변경 내용

## 모델 파이프라인

- `best.pt`: 전체 CCTV 프레임에서 차량 탐지
- 차량별 bbox를 crop
- `tire_level.pt`: 각 차량 crop에서 타이어 침수 단계를 우선 판정
- 타이어가 한 건도 검출되지 않은 차량 crop만 `car_flood_cls.pt`로 차체 침수 단계 판정
- `tire_level.pt`를 `weights/tire_level.pt`에 포함

## CPU 병목 수정

기존 `vehicle_flood_pipeline._predict()`는 CPU일 때 vehicle/tire/body 모델이 하나의 전역 `_CPU_PREDICT_LOCK`을 공유했습니다. V8.5.25에서는 전역 CPU lock을 제거하고 모델 종류별 lock만 사용합니다. 동일 YOLO 객체의 동시 predict는 막지만 `best.pt` 차량 탐지와 `tire_level`/`car_flood_cls` 단계가 서로 불필요하게 한 lock에서 직렬 대기하지 않습니다.

## CPU / GPU 분리

- CPU ZIP: `.env`의 `AI_DEVICE=cpu`
- GPU ZIP: `.env`의 `AI_DEVICE=cuda`
- GPU ZIP은 CUDA를 사용할 수 없으면 조용히 CPU로 떨어지지 않고 명확한 오류를 내도록 했습니다.

## pohang_cctv.py

사용자가 이번 대화에서 첨부한 `pohang_cctv.py`를 기준 파일로 교체했습니다. V8.5.24의 WebSocket 엔드포인트와 호환되도록 `live_transport_packet()` 및 raw-interest lease만 보완했고, CPU/GPU 강제 선택을 따르도록 장치 판별을 연결했습니다.

## 실행

VS Code PowerShell에서 기존 방식 그대로 실행합니다.

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
python -m app.main
```

브라우저: `http://127.0.0.1:8000`
