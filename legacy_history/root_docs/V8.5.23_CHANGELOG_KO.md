# V8.5.23 변경 내역

이번 버전은 사용자가 보내 준 2026-08-15 녹화 영상에서 확인된 세 가지 문제를 대상으로 수정했습니다.

## 1. 여러 CCTV를 열었을 때 영상이 많이 끊기는 문제

V8.5.22에서는 각 CCTV가 다음 HLS 조각을 현재 조각 재생이 끝난 뒤 내려받는 구간이 남아 있어 세그먼트 경계마다 짧은 정지가 발생할 수 있었습니다. V8.5.23은 `_HlsSegmentPrefetcher`를 사용해 현재 조각을 재생하는 동안 다음 조각을 최대 2개까지 미리 내려받습니다. 재생 순서도 최신 조각으로 건너뛰지 않고 다음 조각부터 순차적으로 소비합니다.

HLS 다운로드 응답은 사용 후 명시적으로 닫아 장시간 실행 시 HTTP 연결/소켓이 누적되지 않게 했습니다. HLS 초기 연결이 실제 오류 상태라면 긴 hard timeout까지 기다리지 않고 약 1.6초 뒤 직접 VideoCapture 경로를 한 번 시도합니다. 직접 캡처 재연결 코드에 중복으로 `_open_capture()`가 두 번 호출되던 부분도 제거했습니다.

브라우저 AI 화면은 장시간 multipart MJPEG 연결 대신 `/api/cctv/frame-annotated`의 짧은 JPEG 요청을 사용합니다. 서버는 다음 AI 프레임을 기다리면서 HTTP worker를 잡아두지 않고 현재 최신 JPEG를 즉시 반환합니다. 브라우저는 `X-CCTV-Frame-Seq`가 바뀔 때만 새 화면을 적용합니다.

여러 창이 열렸을 때 모든 카메라가 동일한 속도로 YOLO를 계속 실행해 영상 렌더링을 굶기지 않도록, 포커스된 CCTV는 빠른 차량 검출 주기를 유지하고 비포커스 CCTV는 약 1.75초 이상 간격으로 차량 박스를 갱신합니다. 침수 단계 분류도 비포커스 창에서는 더 낮은 주기로 수행합니다. CPU 환경에서는 차량/타이어/차체 모델 추론을 하나의 전역 잠금으로 직렬화해 여러 PyTorch 추론이 동시에 CPU를 점유하지 않도록 했습니다.

## 2. 마지막으로 선택한 CCTV에만 박스가 표시되던 문제

V8.5.22의 프런트엔드는 선택한 마지막 CCTV만 annotated 스트림으로 유지하고 나머지 창은 raw 화면으로 내리는 구조가 남아 있었습니다. V8.5.23은 **열려 있는 모든 CCTV 창을 annotated 상태로 유지**합니다.

포커스는 이제 박스 표시 여부를 결정하지 않고 AI 갱신 우선순위만 결정합니다. 따라서 정렬해 둔 여러 CCTV에 모두 차량/침수 박스가 유지됩니다.

## 3. 잘못된 차량 박스와 박스 깜빡임 개선

차량 기본 confidence를 `0.22`, 원거리 rescue confidence를 `0.18`로 조정했습니다. 35% 미만의 약한 박스는 한 번 검출됐다고 바로 표시하지 않고 다음 detector pass에서 같은 위치에 다시 검출되어야 확정합니다. 녹화에서 보인 표지판·가니트리·도로 구조물의 일회성 저신뢰 박스를 줄이기 위한 변경입니다.

저신뢰 차량의 optical-flow 박스는 높은 신뢰도 차량보다 더 높은 inlier 비율을 요구하도록 했습니다. AI 처리 시간이 길어져 flow 안전 구간이 지난 경우에는 박스를 즉시 삭제하거나 계속 움직이지 않고, 마지막 검증 위치에서 잠시 고정한 뒤 최대 3~5초 범위에서만 유지합니다. 이로써 여러 창 AI가 순차 처리될 때 박스가 사라졌다 다시 생기는 현상과 배경 텍스처를 따라 박스가 이상하게 이동하는 현상을 함께 줄였습니다.

## 4. CCTV를 오래 켜 두면 화면이 사라지는 문제

실제 화면 `<img>`에 새 Blob URL을 바로 넣지 않습니다. 새 JPEG를 보이지 않는 Image 객체에서 먼저 완전히 디코딩한 뒤 성공했을 때만 화면을 교체합니다. 디코딩 실패/timeout이면 기존 화면을 그대로 유지합니다.

서버 재연결 중에도 한 번이라도 실제 CCTV 프레임이 성공한 적이 있으면 `CCTV RETRY` 상태 JPEG가 기존 실제 화면을 덮어쓰지 않습니다. HLS prefetcher 종료 시 대기 중 임시 파일을 정리하고 짧게 thread join하며, 스트리밍 HTTP response도 확실히 close합니다.

## 기본 설정 변경

- `VEHICLE_DETECTION_CONFIDENCE=0.22`
- `VEHICLE_DETECTION_RESCUE_CONFIDENCE=0.18`
- `STAGE_BOX_DETECTION_INTERVAL_SECONDS=0.65`
- `STAGE_STREAM_INTERVAL_SECONDS=1.80`
- `AI_CPU_THREADS=3`

- `python -m py_compile app/main.py app/pohang_cctv.py app/vehicle_flood_pipeline.py app/config.py`
- `node --check app/static/app.js`
- `PYTHONPATH=. pytest -q` → **65 passed**

실제 포항 외부 CCTV 원본 서버의 네트워크 상태/송출 중단 자체는 프로그램이 복구할 수 없습니다. 원본 송출이 살아 있는 상황에서 클라이언트/서버/HLS/AI 처리 때문에 생기는 정지와 끊김을 복구하도록 수정한 버전입니다.
