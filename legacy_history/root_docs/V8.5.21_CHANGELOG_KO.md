# V8.5.21 변경 내역

## 1. CCTV 창을 열었을 때 즉시 화면이 나오도록 수정

### 브라우저의 지속 연결 제한 회피
V8.5.20은 열린 CCTV마다 `/api/stream-raw` MJPEG 연결을 계속 유지하고, 선택된 CCTV에는 `/api/stream-annotated` 연결을 하나 더 유지했습니다. Chrome/Chromium이 HTTP/1.1에서 같은 호스트에 허용하는 지속 연결 수가 적기 때문에 CCTV를 여러 개 열면 새 스트림 및 상태 API가 브라우저 대기열에 들어갈 수 있었습니다.

V8.5.21에서는 다음 구조로 변경했습니다.

- 선택된 CCTV: 지속형 AI MJPEG 1개만 사용
- 나머지 CCTV: `/api/cctv/frame-raw`의 짧은 JPEG 요청을 약 5fps로 갱신
- 선택 CCTV를 바꾸면 이전 AI MJPEG를 먼저 종료한 뒤 새 AI MJPEG를 시작
- AI 스트림이 준비되는 동안 짧은 raw JPEG를 아래에 표시하여 검은 화면을 줄임

이에 따라 CCTV 창 수가 늘어나도 창마다 지속 HTTP 연결을 하나씩 점유하지 않습니다.

### 네트워크 CCTV는 HLS를 먼저 시도
포항 HTTP CCTV는 일반적으로 HLS로 전달되므로, V8.5.20처럼 OpenCV 네트워크 open timeout을 먼저 기다린 뒤 HLS로 넘어가지 않고 브라우저형 헤더가 포함된 HLS 경로를 먼저 빠르게 시도합니다. HLS가 아닌 주소일 때만 제한된 OpenCV 직접 연결을 다시 시도합니다.

- OpenCV 네트워크 open timeout: 1.8초 -> 1.2초
- read timeout: 0.7초 -> 0.6초
- quick HLS playlist/segment timeout 단축
- 한번 성공한 HLS media playlist는 계속 재사용
- CCTV worker idle 유지시간: 2초 -> 8초 (빠른 재열기 시 연결 재사용)

## 2. 자동 정렬 후 CCTV 창 스크롤 수정

V8.5.20에서는 `.cctv-history`가 `flex:none` 성격을 계속 가지고 고정 높이 395px을 유지했습니다. 정렬된 창 높이가 이보다 작아지면 기록 영역 자체가 부모 창 아래쪽에서 잘렸기 때문에 세로 스크롤바의 맨 아래와 마지막 기록 행에 도달할 수 없었습니다.

V8.5.21에서는:

- CCTV 영상 영역과 기록 영역이 정렬된 창 높이에 맞춰 flex-shrink 되도록 변경
- `.cctv-history`에 `min-height:0`, `overflow-y:auto` 적용
- 자동 정렬 창에서는 영상/기록 영역을 45%/55% 기준으로 가변 배치
- 스크롤바 공간을 안정적으로 유지하도록 `scrollbar-gutter: stable` 적용

따라서 기록 영역이 표시되는 크기의 정렬 창에서는 스크롤을 끝까지 내려 마지막 행까지 볼 수 있습니다.

## 3. 침수 단계 측정 차량 박스 개선

### 잘못된 detector 입력 해상도 수정
V8.5.20은 설정에 `VEHICLE_DETECTION_IMGSZ=960`이 있어도 실제 live box detector에 `STAGE_INFERENCE_IMGSZ=416` 기반 크기를 전달했습니다. 넓은 교차로 CCTV에서 작은/원거리 차량이 크게 축소되어 박스 수가 적어지는 원인이었습니다.

V8.5.21은:

- 차량 박스 detector(best.pt): `VEHICLE_DETECTION_IMGSZ` 사용 (최대 960)
- 침수 단계 tire/body classifier: 기존 작은 `STAGE_INFERENCE_IMGSZ` 유지

즉 박스 좌표 검출 해상도와 침수 단계 분류 해상도를 분리했습니다.

### tiled rescue가 1~2대 검출 후 꺼지던 문제 수정
V8.5.20은 이전 프레임에 차량 박스가 하나라도 있으면 원거리 차량용 tiled rescue를 사실상 비활성화했습니다. V8.5.21은 검출/추적 차량 수가 설정된 목표 개수보다 적으면 약 1.15초 간격으로 rescue를 다시 허용합니다.

패키지 기본값도 다음처럼 조정했습니다.

- `VEHICLE_DETECTION_RESCUE_MIN_COUNT=6`
- `VEHICLE_DETECTION_RESCUE_CONFIDENCE=0.05`
- `VEHICLE_DETECTION_RESCUE_IMGSZ=704`
- `VEHICLE_DETECTION_RESCUE_OVERLAP=0.18`

### CPU 추론 중 박스가 사라지는 현상 완화
고정 0.65초 후 박스를 지우던 정책을 detector 실제 소요시간을 반영하는 동적 tracking 유지시간으로 변경했습니다. 기본 `STAGE_TRACKING_MAX_FLOW_SECONDS`도 1.35초로 조정하고 history를 96프레임으로 늘렸습니다. 단, 오래된 박스가 도로 텍스처를 계속 따라가지 않도록 최대 유지시간은 제한합니다.
