# V8.5.31 변경사항

이번 버전은 사용자가 제공한 V8.5.28 녹화와 Claude의 `device-fallback-fix` ZIP을 비교해서 만들었습니다.

## 1. CCTV 미세 버퍼링 감소
- HLS는 V8.5.28의 live-edge/latest-only 방식을 유지했습니다. Claude ZIP의 1세그먼트 지연/2개 큐 방식은 다시 적용하지 않았습니다.
- AI 입력 프레임은 최대 960px을 유지해 차량 검출 해상도를 보존합니다.
- 브라우저로 보내는 annotated JPEG만 최대 640px로 축소해 4~6개 창 동시 JPEG 인코딩/디코딩 부하를 줄였습니다.
- GPU 렌더는 12fps, raw는 10fps로 조정하고 WebSocket은 선택 창 약 12fps, 정렬 창 약 8fps로 최신 프레임만 전송합니다.
- WebSocket 전송 순서는 선택된 CCTV를 항상 먼저 처리합니다.

## 2. 차량/침수 박스가 `vehicles 0`으로 사라지는 문제
- `best.pt`가 낮은 confidence 차량을 아예 반환하지 못하던 문제를 막기 위해 GPU 추론 후보 threshold를 0.025까지 낮췄습니다.
- 최종 표시 여부는 YOLO threshold가 아니라 후처리 + 시간축 확인으로 결정합니다.
- full-frame 후보는 7.5% 이상이면 즉시 표시, 더 약한 후보는 2~3회 같은 위치에서 재검출되면 확정합니다.
- 이동 차량의 낮은 confidence 박스가 매번 hit 1로 리셋되지 않도록 IoU/중심거리 확인 범위를 완화하고 confirmed 상태를 유지합니다.
- 확정 후보가 아직 하나도 없어도 raw 후보가 존재하면 상위 3개를 `CHECK` 임시 박스로 먼저 표시합니다. 이 임시 박스는 tire/body 침수단계 판정에는 넣지 않습니다.
- 확정된 차량만 기존 요청 순서 `best.pt -> 차량 crop -> tire_level.pt -> 타이어 미검출 시 car_flood_cls.pt`로 판정합니다.

## 3. Claude ZIP에서 반영한 부분
- `AI_DEVICE=cuda`인데 CUDA 런타임이 없는 경우 모델 전체가 None이 되는 대신 CPU로 자동 fallback하고 콘솔에 1회 경고를 출력하는 아이디어를 반영했습니다.
- 반대로 Claude ZIP의 높은 차량 threshold(0.24~0.26), HLS 1세그먼트 지연, 2개 prefetch FIFO는 현재 증상과 반대라 적용하지 않았습니다.
