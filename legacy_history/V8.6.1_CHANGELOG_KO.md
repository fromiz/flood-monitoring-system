# V8.6.1 변경사항 — cuDNN 가변 shape 지연 제거 + 세부 타이밍

V8.6.0의 중앙 GPU Scheduler 구조는 유지하면서, Claude가 지적한 `torch.backends.cudnn.benchmark=True`를 제거했습니다.

## 왜 바꿨나

PyTorch 공식 문서상 cuDNN benchmark/autotuner는 새로운 convolution size parameter 조합을 만나면 여러 알고리즘을 benchmark한 뒤 결과를 캐시합니다. 이 프로젝트는 차량 전체 프레임, 2x2 rescue tile, CLAHE, 그리고 크기/비율이 다양한 차량 crop(tire/body)을 사용하므로 지연 예측 가능성을 우선해 benchmark를 끕니다.

```python
torch.backends.cudnn.benchmark = False
```

`torch.set_float32_matmul_precision("high")`은 그대로 유지합니다.

## 중요한 판단

V8.5.37의 `detector_ms`는 순수 CUDA kernel 시간만이 아니라 기존 lock/queue 대기와 full/rescue/CLAHE 전체 경로를 포함했습니다. 따라서 40~95초 지연을 `cudnn.benchmark` 하나만의 원인으로 단정하지 않습니다. V8.6.0에서 중앙 scheduler로 동시 실행을 제거했고, V8.6.1에서 autotune 변수까지 제거해 두 원인을 분리합니다.

## 새 로그

시작 시:

```text
CUDA61 tuning cudnn_benchmark=False cudnn=... torch=... cuda=... gpu=...
```

개별 중앙 scheduler 호출이 2초 이상이면:

```text
AI SCHED61 slow kind=vehicle batch=... run_ms=... queue_ms=... imgsz=... rect=... shapes=... cudnn_benchmark=False ...
```

차량 detector 전체 경로가 2초 이상이면:

```text
DET61 slow total_ms=... full_ms=... rescue_ms=... clahe_ms=... imgsz=... frame=... raw_candidates=...
```

이제 `full`, `rescue tile`, `CLAHE` 중 어디에서 지연되는지도 확인할 수 있습니다.

## 유지 사항

- 중앙 GPU single-owner scheduler 유지
- 해결된 HLS/영상 버퍼링 경로 유지
- `best.pt -> 차량 crop -> tire_level.pt -> 타이어 미검출 시 car_flood_cls.pt` 순서 유지
- 하단 침수 알림은 단계가 변할 때만 표시
- 임계값을 추가로 추측 조정하지 않음
