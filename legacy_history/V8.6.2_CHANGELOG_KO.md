# V8.6.2 변경사항 — 실제 best.pt 갱신 주기 단축 + 자동 부하 완화

## 왜 바꿨나
사용자 V8.6.1 로그에서 워밍업 1회를 제외한 best.pt 전체 detector 시간은 대체로 약 40~110ms였고, 중앙 vehicle queue는 거의 항상 0이었습니다. WebSocket 결과 age도 대부분 0.02~0.34초였습니다. 즉 GPU 병목은 해결됐지만, 차량 geometry를 요청하는 기본 주기(약 0.24초, 비포커스 약 0.276초)가 움직이는 차량에서 약간의 시각적 후행을 만들 수 있었습니다.

## 핵심 수정
- 중앙 GPU scheduler / micro-batch / `cudnn.benchmark=False`는 그대로 유지.
- Optical Flow나 미래 위치 extrapolation으로 박스를 꾸미지 않음.
- scheduler가 여유로울 때 실제 `best.pt`를 기본 **0.18초** cadence로 더 자주 요청.
- 비포커스 창은 fast cadence에 1.12배만 적용해 여러 CCTV가 열려도 충분히 자주 갱신.
- vehicle/stage queue, 최근 vehicle run time, 최근 queue wait가 커지면 자동으로 normal/busy cadence로 복귀.
- busy 기본값은 0.34초이며 GPU 혼잡이 풀리면 다시 fast로 복귀.
- `CCTV BOX62`/`CCTV WS62`에 `cadence=fast|normal|busy/초`를 표시.
- `/api/cctv/worker-status`에 `ai_cadence_mode`, `ai_interval_seconds` 추가.

## 변경하지 않은 안전장치
- HLS latest-only/버퍼링 개선 구조 유지.
- 서버 단일 box renderer 유지.
- 중앙 GPU single predict owner 유지.
- `best.pt -> vehicle crop -> tire_level.pt -> tire 미검출 시 car_flood_cls.pt` 순서 유지.
- 하단 침수 알림은 단계 변화 때만 표시.

## 기본 adaptive 값
```text
AI_ADAPTIVE_CADENCE_ENABLED=true
AI_GEOMETRY_FAST_INTERVAL_SECONDS=0.18
AI_GEOMETRY_BUSY_INTERVAL_SECONDS=0.34
AI_GEOMETRY_NONFOCUSED_MULTIPLIER=1.12
```

이 값들은 V8.6.1 사용자 로그의 실제 40~110ms steady-state GPU 성능에 맞춰 보수적으로 정했습니다. 무조건 0.10초 이하로 밀어 넣지 않아 stage starvation이나 버퍼링 재발 위험을 피합니다.
